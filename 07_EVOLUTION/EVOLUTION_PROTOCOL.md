# CAR SERVICE 06 — EVOLUTION PROTOCOL

## Purpose

Each project must improve the immersive production system.

## After every validated milestone

Record:

1. what worked
2. what failed
3. why it failed
4. what was changed
5. what should become reusable
6. what should never be repeated

## Important distinction

Do not promote a project-specific solution into the core merely because it looks good.

A rule becomes reusable only when:

- it solved a real problem
- it can generalize
- it does not depend on the project's visual identity
- it survives responsive and reduced-motion testing

## Failure library

Track recurring failures such as:

- scroll/video desynchronization
- camera movement without subject
- over-complex WebGL
- mobile degradation
- visual clutter
- generic luxury aesthetics
- performance collapse caused by media
- transition effects without narrative meaning

## Evolution candidate format

```text
PROBLEM:
OBSERVATION:
CAUSE:
SOLUTION:
GENERALIZABLE RULE:
VALIDATED ON:
LIMITATIONS:
```

## End-of-project extraction

At project completion, extract only validated engineering and experience principles into the global immersive knowledge base.
