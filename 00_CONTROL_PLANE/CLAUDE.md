# CAR SERVICE 06 — CLAUDE OPERATING CONTRACT

## Mission

Build a premium, immersive, commercially credible sector-demo website for CAR SERVICE 06.

The objective is not to reproduce an existing website. The objective is to demonstrate what a high-end digital experience can become for this sector.

## Non-negotiable workflow

BUILD → INSPECT → CRITIQUE → CORRECT → RE-INSPECT → VALIDATE

Never stack a new layer on top of an unvalidated layer.

## Core priorities

1. Immersion
2. Cinematography
3. Visual quality
4. Narrative coherence
5. Scroll quality
6. Performance
7. Accessibility
8. SEO
9. Conversion
10. Technical elegance

A technically correct but visually weak result is not acceptable.

## Anti-template rule

Reject solutions resembling:

- generic car wash landing pages
- SaaS layouts
- dashboard UI
- card grids as the main experience
- generic hero/video/text blocks
- arbitrary gradients
- glassmorphism
- excessive glow
- generic parallax
- repeated fade-ins
- decorative 3D with no narrative purpose
- “AI luxury” aesthetics

## Truth rule

Never invent:

- services
- prices
- guarantees
- certifications
- reviews
- legal status
- geographic coverage beyond supplied evidence
- opening hours
- commercial claims
- affiliations with vehicle manufacturers

When a fact is uncertain, mark it `TO_CONFIRM`.

## Reuse rule

Reuse proven engineering patterns from previous projects when useful.

Do NOT copy another project's:

- visual identity
- scene composition
- typography system
- timing
- transitions
- narrative
- content
- art direction

The reusable asset is the method, not the appearance.

## Decision rule

Technology serves experience.

If a technology does not materially improve the experience, do not add it.

If an existing decision degrades quality, performance, accessibility, SEO or comprehension, Claude may replace it and document the reason.

## Visual validation

`npm run build` is not visual validation.

Every major milestone must be inspected in a running browser at desktop and mobile sizes.

## Definition of done

Do not declare completion until the experience passes the validation protocol and the remaining defects are explicitly listed.
